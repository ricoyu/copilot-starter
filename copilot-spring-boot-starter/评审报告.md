> 评审对象：copilot-starter / copilot-spring-boot-starter

> 标注：【小赫复核确认】＝本人读源码原文核对过；【实测(子代理)】＝子代理以探针/读上游源码核对；【代码分析】＝读代码路径推导，需在特定环境复现

## 概述
`copilot-spring-boot` 的自动装配壳。最大问题是 ObjectMapperBeanPostProcessor 写好了却没接进装配（本 starter 里是死类），以及两处条件注解写法导致用户覆盖/关开关失效。

## P1
### 1. ObjectMapperBeanPostProcessor 未注册进自动装配，Jackson 增强配置全部失效
`.../autoconfig/processor/ObjectMapperBeanPostProcessor.java:33,46-57`
- 现象：该类实现 `SmartInitializingSingleton`，负责把 Spring 容器的 ObjectMapper 交给静态 `JacksonUtils`，并应用 `copilot.jackson.deserializers/serializers`、`fieldNameQuote` 等配置。但 `grep` 全仓：本 starter 内没有任何 `@Bean` 方法、AutoConfiguration.imports 条目或组件扫描引用它（web-starter 用的是另一个 `CopilotJacksonObjectMapperPostProcessor`）。【实测(子代理)：装配点 grep=0，小赫复核确认】
- 影响：只用 `copilot-spring-boot-starter`（非 Web）的应用里，「容器 ObjectMapper 交给 JacksonUtils」和 `copilot.jackson.*` 配置整块不生效；用户按文档写了 yml 也没有任何反应，且无报错。
- 修复：在 `CopilotAutoConfiguration` 里加 `@Bean @ConditionalOnMissingBean ObjectMapperBeanPostProcessor`；若设计意图就是让 web-starter 那个 BPP 接管，则删掉本类，避免两份实现各写一半、行为漂移。

### 2. 两个 @Bean 缺 @ConditionalOnMissingBean，用户自定义会双份装配
`.../autoconfig/CopilotCacheAutoConfiguration.java:30-38`
- `redisListenerProcessor()`、`cacheAspect()` 均无条件注册。用户自定义同类型 Bean（想改延迟、加监控）时，自动配置 Bean 照样创建 → 容器里出现两个 `CopilotCacheEvictAspect`（`@Before/@AfterReturning` 各执行两遍，双倍删除+双倍调度）和两个 `RedisListenerProcessor`（订阅消息再多叠一层重复，与主库报告 #1 叠加）。用户只能整包 `copilot.cache.enabled=false` 关掉全部功能。【代码分析，Spring 条件装配规则确定】
- 修复：两个 `@Bean` 各加 `@ConditionalOnMissingBean`；类上补 `@ConditionalOnClass(JedisUtils.class)`，防止 exclude 掉 copilot-cache 后启动直接 `NoClassDefFoundError`。

### 3. @ConditionalOnProperty 用 camelCase 键，kebab-case 配置关不掉开关
`.../autoconfig/CopilotAutoConfiguration.java:53,60`
- 条件用 `copilot.asyncTransaction`、`copilot.enablePostInitialize`。`@ConditionalOnProperty` 走 `Environment.getProperty` 精确匹配，不做 relaxed binding；而 Boot 官方推荐、IDE 补全默认输出的是 kebab-case（`copilot.async-transaction: false`、`copilot.enable-post-initialize: false`）。
- 影响：用户写 kebab-case 时条件读不到属性 → `matchIfMissing=true` → 明明把开关设为 false，TransactionEvents/PostInitialize 处理器仍被装配；而 `@ConfigurationProperties` 侧按 relaxed 绑定成了 false，两边判断不一致更难排查。【代码分析】
- 修复：条件 value 改成 kebab-case 规范名（字段名不变，camelCase 配置仍被 relaxed 兼容）。

### 4. starter 在 classpath 根携带 application.properties
`copilot-spring-boot-starter/src/main/resources/application.properties:1`
- 文件内容：`spring.main.allow-circular-references=true`。库 jar 在根携带 application.properties 是事故源：若宿主应用自己没有 application.properties，`classpath:/application.properties` 会命中 starter 这份，给整个应用悄悄打开「允许循环依赖」开关（Boot 2.6+ 默认禁止循环依赖，是刻意暴露设计问题）；若应用有自己的文件，谁生效取决于 classpath 顺序，行为不确定。【小赫复核确认：文件存在且仅此一行】
- 修复：删掉该文件。确需该默认值时改为文档说明，或写一个仅在属性缺失时补默认值的 `EnvironmentPostProcessor`。

### 5. aspectjweaver 版本写死为 1.8.7，把宿主应用拖回 2015 年
`copilot-spring-boot-starter/pom.xml:33-42`
- starter 直接依赖并写死 `org.aspectj:aspectjweaver:1.8.7` 与 `aspectjrt:1.8.7`。1.8.7 的 ASM/BCEL 最高识别 Java 8 字节码。starter 是直接依赖，会把 Boot 3.2.4 父 pom 管理的 1.9.21 降到 1.8.7。
- 影响：任何走 AspectJ 字节码解析的路径（泛型 `@within`、影子匹配、`@Configurable`、spring-aspects）遇到 Java 21 的 class 会抛 `Unsupported class file major version 65`；与 Spring Framework 6.1 要求的 AspectJ 1.9.x 组合不匹配。【实测(子代理)：版本号读自 pom，降级事实由 pom 直接证实】
- 修复：删掉两处 `<version>` 交给 Boot 父 pom 管理，或直接用 `spring-boot-starter-aop`。

## P2
### 6. registerModule 在循环内被调 N 次 + 吞异常
`.../processor/ObjectMapperBeanPostProcessor.java:71-87,92-108`
- 同一个 `SimpleModule` 在 for 循环体内被 `registerModule` 多次，靠 SimpleModule 的 typeId=内容哈希这一 Jackson 内部细节才勉强得到「后者覆盖前者」，语义脆弱且 O(n²)；实例化失败仅 `log.error` 后 continue，用户配的自定义序列化器被悄悄丢掉，线上表现为偶发反序列化行为不符且无人知配置未生效；`Class.newInstance` JDK9+ 已废弃。【代码分析；此段当前因 #1 实际不执行，属激活后隐患】
- 修复：`registerModule` 移到循环外只调一次；`getDeclaredConstructor().newInstance()`，失败抛 `IllegalStateException` 让启动显式失败。

### 7. 装饰状态集合非线程安全
`.../processor/ObjectMapperDecorationTracker.java:14-21`
- `Collections.newSetFromMap(new IdentityHashMap<>())` 不保证线程安全。当前两个调用方都在启动线程，但 BeanPostProcessor 在并行初始化（refresh 期被 @Async 调用、ContextRefresher 并行）下可能多线程进入 `markDecorated`，竞态下同一 mapper 被判「未装饰」两次 → decorate 执行两遍（部分配置非幂等）。static 集合永不清理，devtools 频繁重启时旧 mapper 被强引用滞留。【实测(子代理)：该类无并发原语】
- 修复：用 `Collections.newSetFromMap(Collections.synchronizedMap(new IdentityHashMap<>()))`；提供 reset 或用弱引用支持上下文重启。
