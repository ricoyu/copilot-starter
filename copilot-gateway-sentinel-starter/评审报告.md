## 概述
Sentinel 网关适配壳，只有 1 个自动配置 + 1 个 block 处理器，规模小，问题集中在限流响应的 HTTP 语义。

## P2
### 1. 被限流/熔断的请求对外返回 HTTP 200
`.../sentinel/handler/GatewayBlockRequestHandler.java:43-45,61-63`
- JSON 分支 `response.setStatusCode(HttpStatus.OK)` 返回 200 + 业务错误码；html 分支同样 200 且 `contentType` 声明 TEXT_PLAIN 却往 body 写 JSON 字符串。两处使用已废弃的 `BodyInserters.fromObject`（6.1.5 jar 中仍存在，仅 deprecated）。
- 影响：CDN、客户端重试策略、告警、SLA 统计全部把「被限流」当成功请求；浏览器路径拿到 content-type 与内容不符的裸文本。与 copilot-gateway 报告里「鉴权失败也回 200」是同一种约定，若为兼容旧前端的有意决策，应至少提供开关。【实测(子代理)读全文件】
- 修复：限流 429、熔断 503（或配置开关）；htmlErrorResponse 统一 APPLICATION_JSON 输出结构体。

### 2. 装配核对
- imports 唯一一行 `CopilotGatewaySentinelAutoConfig` 存在，无幽灵注册；该类以 `@ConditionalOnClass` 门控注册 BlockRequestHandler，与阿里 `SentinelSCGAutoConfiguration` 的 `ObjectProvider<BlockRequestHandler>` 接管机制兼容（上游源码核对）。注意与 copilot-gateway-starter 报告 #1 的双注册问题是同一条链路：本 starter 与 gateway-starter 同引时，CopilotSentinelGatewayAutoConfig 的处置以彼处为准。【实测(子代理)】
