> 评审时间：2026-09-18　范围：src/main/java 全部源码 + pom.xml + META-INF 自动装配

> 标注：【复核确认】＝评审人读源码/字节码原文核对；【实测】＝探针/上游源码核对过；【分析】＝代码路径推导

## 概述
网关自动装配壳。装配条件有两处会造成「以为开了其实没开」/「以为装一个其实装两个」的问题；CORS 配置类是当前问题最集中的一个。

## P1
### 1. CopilotSentinelGatewayAutoConfig 未登记进 imports，且与阿里自动配置存在双注册风险
`.../autoconfig/CopilotSentinelGatewayAutoConfig.java:20-28` + `src/main/resources/META-INF/spring/...AutoConfiguration.imports`
- 两面问题：①该 `@Configuration` 没写进 imports 第 7 行——标准引入 starter 时它不生效，只有组件扫描覆盖到该包才装载；②子代理反编译 spring-cloud-alibaba-sentinel-gateway 2023.0.1.0 确认：阿里官方 `SentinelSCGAutoConfiguration` 自己无条件注册 `sentinelGatewayFilter`（`spring.cloud.sentinel.scg.enabled` 默认 true），本类的 `@Bean SentinelGatewayFilter` 又无 `@ConditionalOnMissingBean`——一旦两条路径同时满足（扫描 + 阿里自动配置），每个请求进 Sentinel 两次，限流计数翻倍，阈值形同减半。【实测(子代理反编译上游 jar)】
- 修复：推荐直接删除本类（阿里 starter 已通过 `ObjectProvider<BlockRequestHandler>` 接管 GatewayBlockRequestHandler，链路完好）；若保留则登记 imports + 加 `@ConditionalOnMissingBean(SentinelGatewayFilter.class)`。

### 2. jwt-token=true 时鉴权过滤器静默消失（fail-open）
`.../autoconfig/CopilotGatewayAuthAutoConfiguration.java:23,30`
- 外层 `copilot.gateway.auth.enabled=true` 才装配；内层又要求 `copilot.gateway.auth.jwt-token` 为 false（缺省 true）。把 jwt-token 配成 true 时 AuthenticationFilter 这个 bean 不创建，网关变成完全不鉴权且无任何报错——「auth.enabled=true 即有鉴权」的运维直觉被这个隐藏开关打破。全仓也没有任何 JWT 校验 filter 实现（jjwt 依赖与 TokenInfo 只是预备），jjwt 0.10.8 解析失败绕过面因此不存在，但「未实现」本身是当前缺陷。【实测(子代理 grep)】
- 修复：删除 jwt-token 条件；或在 jwt-token=true 且无 JWT filter 时启动抛 IllegalStateException 明确提示未实现。

## P2
### 3. GatewayCorsConfig 三处不一致
`.../autoconfig/GatewayCorsConfig.java:22-41`
- ①`corsWebFilter()` 注入了 CopilotGatewayProperties 却一行不读：allowCredentials(true)+allowedOriginPattern("*")+头/方法全通配全部硬编码——`copilot.gateway.cors.*` 配置完全无效，且 allowCredentials+通配 Origin 组合等于向任意来源回显 Origin 并允许带 Cookie，高危配置；②`@ConditionalOnProperty(matchIfMissing=false)` 与属性类 `CORS.enabled` 默认 true 两处开关语义相反：不显式配置时 bean 根本不建，与默认值承诺相反；③类上的 `@Order(HIGHEST_PRECEDENCE)` 对 @Bean 产物的排序无效（WebFilter 排序看 bean 定义不看配置类注解），造成「优先级最高」的假象。【实测(子代理)】
- 修复：从 properties 逐项装配；条件与默认值统一到一处；`@Order` 挪到 @Bean 方法；生产默认 allowCredentials=false。

### 4. CopilotRestTemplate bean 无任何条件注解
`.../autoconfig/CopilotGatewayAutoConfiguration.java:19-31`
- `@Bean @LoadBalanced CopilotRestTemplate` 无 `@ConditionalOnMissingBean`（用户无法干净覆盖），`@LoadBalanced` 与该类内部自行做服务名解析的设计叠加（类注释明确说就是为了绕开 @LoadBalanced 的启动时序），若应用又引入 spring-cloud-loadbalancer 会二次解析。它引用的还是 gateway 包里覆写错 doExecute 重载的旧拷贝（见 copilot-gateway 报告 P0#2）。【实测(子代理)】
- 修复：加条件注解；换用 copilot-spring-cloud 的新实现后移除 `@LoadBalanced`。

### 5. imports 全量核对结果（无幽灵注册）
- 6 行注册（Predicate/Filter/Auto/Exception/Auth/Cors）逐一核对都有对应源文件，`GatewayCorsConfig` 真实存在；行尾 CRLF 不影响 Spring ImportsReader 解析。当前真正的缺口是第 7 个配置类未登记（#1）。【实测：狗蛋本人逐行核对磁盘文件】
