# 代码评审报告：copilot-gateway

> 评审时间：2026-09-18　范围：src/main/java 全部源码 + pom.xml + META-INF 自动装配
> 分级：P0＝线上可触发；P1＝可靠性与正确性；P2＝性能/配置陷阱/技术债
> 标注：【复核确认】＝评审人读源码/字节码原文核对；【实测】＝探针/上游源码核对过；【分析】＝代码路径推导

---

## 概述
网关功能库（全局鉴权过滤器、RestTemplate、计时过滤器、异常处理）。有一个鉴权绕过级漏洞和一个「签名覆写错了重载」导致服务名解析整体失效的问题。

## P0
### 1. 鉴权白名单用未规范化的路径匹配，可用 ../ 与 %2e%2e 绕过
`.../gateway/auth/filter/AuthenticationFilter.java:29,76-83`
- 匹配输入是 `exchange.getRequest().getURI().getPath()`——该值 URL 解码了一次，但没有做路径规范化（`..` 段原样保留）。子代理用 AntPathMatcher 实跑：`match("/public/**","/public/../secret")=true`、`match("/public/**","/public/%2e%2e/secret")=true`；`URI.getPath()` 对 `%2e%2e` 解码回 `..` 也实测过。
- 影响：请求 `/public/%2e%2e/protected` 命中白名单 `/public/**` 免鉴权放行；网关把解码一次后的原始路径转发给后端，后端框架（Spring MVC 的 PathPattern/请求映射）再做规范化，落到受保护接口——经典编码穿越绕过。【实测(子代理探针)，狗蛋复核了取值链源码】
- 修复：匹配前先 `StringUtils.cleanPath(UriUtils.decode(path, UTF_8))`，对仍含 `..`（或其编码形式）的路径直接返回 400；白名单与路由转发使用同一份规范化路径。

### 2. gateway 版 CopilotRestTemplate 覆写错了 doExecute 重载，服务名替换整体不生效
`.../gateway/client/CopilotRestTemplate.java:45-46`
- 该类覆写 4 参 `doExecute(URI, HttpMethod, RequestCallback, ResponseExtractor)`。我本人对 Boot 3.2.4 实际解析到的 spring-web-6.1.5.jar 做了字节码检查（javap -c）：库内全部 5 处 `invokevirtual doExecute` 都指向 5 参新签名 `(URI, String uriTemplate, HttpMethod, ...)`，对 4 参签名的调用计数为 0，且 4 参方法自身只是转发到 5 参的实现。即：Spring 6 的公开入口不再经过 4 参版本，覆写的 `replaceUrl` 永不执行。
- 影响：用 `http://service-name/path` 形式调用时走原生逻辑，直接 DNS 解析服务名失败（UnknownHostException）；该类用于启动期拉取公钥等链路，失败即服务起不来。copilot-spring-cloud 里的同名新类（CopilotRestTemplate.java:53）已改为覆写 5 参签名——这是同一类的旧/新两份拷贝，旧份在网关包。【实测：javap 字节码核对，见 rt615.txt】
- 修复：删除 gateway 包内这份旧拷贝，统一使用 `com.awesomecopilot.cloud.client.CopilotRestTemplate`（starter 的引用同步改）。

## P1
### 3. 鉴权通过后把 mutated exchange 丢掉了，username 头从未传给下游
`AuthenticationFilter.java:68-72`
- line 68-70 构造了带 `username` 头的 `serverWebExchange`，line 72 却 `return chain.filter(exchange)`——用的是原始 exchange，新构造的对象是死变量。
- 影响：①下游永远收不到网关注入的 username；②网关也没有删除客户端自带的 `username` 头，若下游信任该头则可直接伪造身份。【复核确认：源码原文如此】
- 修复：`return chain.filter(serverWebExchange);`，并在 mutate 前 `headers.remove("username")` 防伪造。

### 4. TimeMonitor 过滤器 value=false 时返回 null Mono，整条路由 500
`.../gateway/filter/TimeMonitorGatewayFilterFactory.java:49-51`
- `if ("false".equalsIgnoreCase(value)) return null;`。子代理用 reactor-core 3.6.4 实跑：链路里返回 null Mono 在订阅时抛 NullPointerException。
- 影响：想通过 `TimeMonitor=enabled,false` 关闭计时的路由，该路由全部请求直接失败（chain.filter 根本没被调用）。关闭开关反而炸路由。【实测(子代理探针)】
- 修复：`return chain.filter(exchange);`（关闭计时＝不包装、照常放行）。

### 5. 兜底异常处理不记日志，网关未知错误无从排查
`.../gateway/advice/GatewayExceptionHandlerAdvice.java:55-59`
- `@ExceptionHandler(Throwable.class)` 分支直接 `return Results.status(SYSTEM_ERROR)`，没有任何 log（同文件其余分支都有 log.error）。线上出现 NPE/序列化错误时只有 010500 错误码，日志里无堆栈。【复核确认】
- 修复：补 `log.error("网关未知异常 uri={}", ..., e)`。

## P2
### 6. 鉴权失败被强制改成 HTTP 200
`.../gateway/handler/CopilotErrorWebExceptionHandler.java:90-93`
- GatewayException（token 缺失/无效）时 `errorStatus = HttpStatus.OK`，注释表明是为兼容既有前端的有意选择。代价：401 语义丢失，前端拦截器、监控告警、SDK 重试/跳登录逻辑都看不见认证失败。【复核确认：注释在案】
- 建议：至少对 `Accept: application/json` 的请求返回真 401，或提供配置开关。

### 7. 计时/鉴权路径的日志问题
`TimeMonitorGatewayFilterFactory.java:47,57-62`、`AuthenticationFilter.java:30,33,57`
- 每请求固定 2 条 info，query 参数整串打进日志（token/手机号等敏感值进日志，违反仓库自身的日志脱敏规范）；`log.error("校验令牌异常:{}", e)` 的 `{}` 占位写法错误，slf4j 会丢掉堆栈；鉴权 warn 不带 url 无法定位。【复核确认】
- 修复：降 debug；参数脱敏；`log.error("..., url={}", path, e)` 末位传异常。

### 8. pom 把 spring-cloud-gateway-core 的版本指定为 2.2.10.RELEASE
`copilot-gateway/pom.xml:38-39`（starter 两个模块同样写法；根 pom 还有未引用的 `gateway.version` 属性与注释掉的 4.1.2）
- 本地仓库实测：该坐标 jar 只有 3974 字节、14 个条目，是 Boot 3 时代的一个弃用警告壳，实际功能类由 2023.0.1 BOM 把 `spring-cloud-gateway-server` 解析到 4.1.2（jakarta 线）。当前无运行时故障，但把 Boot 2.x 时代的版本号写在这里极具误导性：哪天 BOM 不再管理该坐标，或有人照抄坐标到 BOM 之外的模块，就会真的引入 javax 注解的旧类造成启动冲突。【实测(子代理 jar 检查+dependency:tree)，狗蛋复核根 pom 属性】
- 修复：删掉三处显式 version 与壳依赖，改声明 `spring-cloud-starter-gateway`（不带版本，由 BOM 管理）；清理根 pom 死属性。

### 9. CopilotGatewayExceptionProperties 是空壳死配置
`.../gateway/properties/CopilotGatewayExceptionProperties.java:16-20`
- 空类 + `@ConfigurationProperties(prefix="copilot.gateway.exception")`，全仓无人注册、无人读取；配置元数据还会为它提示不存在的属性。【实测(子代理 grep)】
- 修复：删除，或补上它本该承载的「错误码→HTTP 状态」映射（正好解决 #6）。
