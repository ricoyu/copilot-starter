## P2
### 1. addHeader 是追加语义，调用方常当 setHeader 用
`.../webflux/utils/WebFluxUtils.java:26-45`
- 基于 `request.mutate().header(name, value)`，对已存在的同名头是追加而非替换，多次调用形成多值头，下游 `getFirst` 拿到的是旧值。方法名与语义相符，但与 Mutator 惯例（多数人预期 header 是覆盖）有认知落差。【实测(子代理)】
- 修复：补一个先 `headers.remove(name)` 再 add 的 `setHeader`。

### 2. requestPath 返回解码后路径
`WebFluxUtils.java:64-66`
- `getURI().getPath()` 已解码（`%2F` 会解开）。若调用方用它做路由前缀/鉴权匹配，存在与网关侧（gateway 报告 P0#1 同源）编码差异导致的匹配错位边界。getHeader 对空 headerName 已有 Assert，其余无问题。【实测(子代理)；【分析】是否被用于安全匹配取决于调用方】
- 修复：需要原始路径时提供 `getRawPath()` 变体并在 javadoc 写明差异。
