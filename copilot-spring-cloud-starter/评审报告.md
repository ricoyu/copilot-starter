## 概述
微服务自动装配壳。最大的问题是幂等功能的配置键在项目内出现三种互不相同的写法，按 README 配置只能开启一半。

## P1
### 1. 幂等开关键名三处不一致，被调侧静默不生效
`.../autoconfig/CopilotSpringCloudAutoConfiguration.java:57 vs 72`
- 调用方 feign 拦截器门控 `copilot.idempotent.enabled`（line 57）；被调方切面门控 `copilot.idemtotent.enabled`（line 72，多了个 t 的拼写错误）；`IdemtotentProperties.java:15` 的 prefix 又是 `copilot.idempotent`；starter readme 与注解 javadoc 再各说各话（共三个不同键）。
- 影响：按 README 配 `copilot.idempotent.enabled=true` 只启用 feign 塞头，被调侧幂等切面根本没装载——整套幂等防护看起来开了实际没有，属安全护栏失效类缺陷。【实测(子代理)；小赫复核两个 @ConditionalOnProperty 原文】
- 修复：统一 `copilot.idempotent.enabled` 一键（或明确两键并同步 readme/javadoc）；`IdemtotentProperties` 类名一并纠正（可留 deprecated 别名）。

## P2
### 2. IdempotentInterceptor 在 feign 重试时把幂等头变成多值
`copilot-spring-cloud/.../feign/interceptor/IdempotentInterceptor.java:54-58`（注册在本 starter）
- javadoc 承诺「接口超时重试时 Feign 携带之前塞的 Idempotent 头」；实际 Retryer 每次重试对同一 template 重新执行 apply，`RequestTemplate.header(name, value)` 是追加语义 → 第二次重试头值变成 `"uuid1,uuid2"`，被调方判重键与首请求不同，SET.sadd 再次成功——在最需要幂等的超时重试场景反而失效。且该 UUID 是 per-RPC 生成，同一用户双击产生的两次请求拿到两个不同令牌，业务重复提交本来就防不住。【实测(子代理)；header 追加语义为 feign 公开文档行为，建议补一个 RequestTemplate 单测坐实】
- 修复：生成的令牌先存调用级上下文，重试时 `removeHeader` 后回填原值；或按 feign `RetryableStatus` 前冻结。文档明确本方案只防传输重试。

### 3. AuthRule.enabled 死字段 + 默认值与文档矛盾
`.../autoconfig/CopilotSpringCloudAutoConfiguration.java:100-110` 对照 `SentinelProperties.java:68`
- 授权规则开关实际由 `@ConditionalOnProperty(matchIfMissing=true)` 直接读 Environment；properties 里的 `AuthRule.enabled` 默认 true 且 `isEnabled()` 零调用，readme 却写「默认 false」。用户改字段值不产生任何行为。另有 line 43-47 两个从未使用的 @Autowired 字段。【实测(子代理)】
- 修复：readme 与代码统一；删死字段/死注入；给三个 feign bean 补 `@ConditionalOnMissingBean`。

### 4. LBProperties 只是 IDE 提示载体
`.../autoconfig/DefaultLBConfig.java:13-14` + `properties/LBProperties.java`
- 金丝雀开关走 `@ConditionalOnProperty(copilot.lb.canary-release.enabled)` 直接读环境，`@EnableConfigurationProperties(LBProperties.class)` 注册的 bean 无任何消费方——用户以为改 properties 对象能热调，实际只是元数据提示。【实测(子代理)】
- 修复：javadoc 注明「仅用于配置提示」，或让条件基于该 bean。

### 5. 自动装配注册核对结果
- imports 两行（CopilotSpringCloudAutoConfiguration、DefaultLBConfig）都真实存在【实测：小赫逐行核对磁盘】；两行都是 `@Configuration` 而非 `@AutoConfiguration`，失去自动配置排序语义——金丝雀依赖 NacosDiscovery 的 bean，建议 `@AutoConfigureAfter(NacosDiscoveryAutoConfiguration.class)`。`CanaryReleaseLoadBalancerConfiguration.defaultLoadBalancer` 的入参 nacosDiscoveryProperties 从未使用（CanaryReleaseRule 内部靠 @Autowired 字段注入获取），删入参、改构造器注入。【实测(子代理)】
