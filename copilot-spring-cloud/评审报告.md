# 代码评审报告：copilot-spring-cloud

> 评审时间：2026-09-18　范围：src/main/java 全部源码 + pom.xml + META-INF 自动装配
> 分级：P0＝线上可触发；P1＝可靠性与正确性；P2＝性能/配置陷阱/技术债
> 标注：【复核确认】＝评审人读源码原文核对；【实测】＝探针/上游源码核对过；【分析】＝代码路径推导

## 概述
微服务支撑库（feign 拦截器/切面、金丝雀负载均衡、RestTemplate、Sentinel 异常处理）。feign 拦截器一条链上有三个可生产触发的问题：Authorization 头被替换成随机 UUID、非 HTTP 线程必炸 NPE、幂等 SET 永不过期。

## P0
### 1. AuthorizationInterceptor 用随机 UUID 冒充 Authorization 头传给下游
`.../cloud/feign/interceptor/AuthorizationInterceptor.java:34-38`
- 类注释承诺「向下游传递 Authorization 请求头」，实际代码取完 request 后从未读取其 Authorization 头，而是 `UUID.randomUUID()` 塞进 `template.header("Authorization", ...)`。
- 影响：下游任何依赖 Authorization 鉴权的服务在这条 feign 链路上必然 401；且该 bean 无属性开关（见 starter 报告 #2），引入 starter 就生效。【复核确认：源码原文核对】
- 修复：`String auth = request == null ? null : request.getHeader("Authorization"); if (isNotBlank(auth)) template.header("Authorization", auth);`

### 2. 四个 feign 组件在同一处 ThreadLocal 上裸取 request，非 HTTP 线程必 NPE
`AuthorizationInterceptor.java:30-31`、`IdempotentInterceptor.java:37-38`、`TenantIdInterceptor.java:37-38`、`feign/aspect/IdempotentAspect.java:42-43`
- 统一模式：`((ServletRequestAttributes) RequestContextHolder.getRequestAttributes()).getRequest()`，无 null 检查。@Async 线程、MQ 消费者、定时任务、CompletableFuture 里发起 feign 调用时 `getRequestAttributes()` 返回 null → NPE，整个调用失败。更荒唐的是 IdempotentInterceptor 取了 request 根本不用，纯属无谓炸点。【实测(子代理)，狗蛋复核两处原文】
- 修复：统一 `Object attrs = RequestContextHolder.getRequestAttributes(); if (!(attrs instanceof ServletRequestAttributes)) return;`；不需要 request 的代码删掉。

### 3. 幂等 SET 永不过期，Redis 无界增长
`.../cloud/feign/aspect/IdempotentAspect.java:41,50`
- key 为 `Idempotent:{类}:{方法}:{参数个数}`，成员是每次调用新造的 UUID，`JedisUtils.SET.sadd` 无任何 TTL（上游 JedisUtils.java:1342 起的 SET 操作族确无过期参数），仅业务异常分支 srem。开 `copilot.idemtotent.enabled=true`（注意这个键名拼写，见 starter 报告 #2）后该 SET 单调增长直到 Redis OOM。另外文档（line 15 与 starter javadoc）声称用 HyperLogLog，实现是 Set。
- 影响：内存泄漏 + 「进程在 proceed 成功前崩溃」的令牌永无清理，合法重试被永久判重。【复核确认：sadd/无 TTL 属实】
- 修复：每令牌独立 key：`SET idem:{token} 1 NX EX ttl`，ttl 按业务重试窗口配置；同步更正文档。

## P1
### 4. CopilotRestTemplate.replaceUrl 重建 URI 时丢掉 query 和 fragment
`.../cloud/client/CopilotRestTemplate.java:109-125`
- `String source = serviceIp + url.getPath(); return new URI(source);`——只取 path，`?kw=x&page=2` 整体消失；`URISyntaxException` 时 log.error 后 `return url` 拿服务名继续发（错误远离根因）。带查询参数的 GET 经此模板调用后参数静默丢失，属数据正确性问题。line 91 的 `replace(serviceName, serviceIp)` 式全量字符串替换在 path 含同名片段时会连 path 一起替换。【复核确认：replaceUrl 全文已读】
- 修复：用 `UriComponentsBuilder.fromUri(url).host(h).port(p).replacePath(path)` 保留 query/fragment；解析异常直接抛出。

### 5. 幂等命中后 return null，调用方拿到「空成功」
`IdempotentAspect.java:50,64-66`
- 判为重复杂仅 log.warn，落到 line 69 `return null`：目标方法不执行，HTTP 200 + 空 body；返回值为原始类型的方法还会拆箱 NPE。调用方无法区分「幂等命中」和「成功但返回空」。【复核确认】
- 修复：命中时抛 DUPLICATE_SUBMISSION 业务错误（参照 web 版 IdempotentIntercepter 的做法）或返回上次结果。

### 6. 金丝雀规则在缺少 current-version 元数据时静默降级为全随机 + 每请求 error 日志
`.../cloud/loadbalancer/CanaryReleaseRule.java:126,131,148-153`
- `version = metadata.get("current-version")` 可为 null；上游 commons-lang `StringUtils.equalsIgCase`（line 412-415）对 beCompared==null 直接 false——未配 metadata 的调用方一二级匹配永远为空，恒走兜底分支：`log.error` 一条 + 在【全部实例】加权随机。开发者流量会打到线上公共实例和其他开发者实例（恰是该功能要防的），无启动期告警，高 QPS 下 error 日志刷屏。实例列表为空时 `new DefaultResponse(null)` 抛 `IllegalStateException: Null instances not allowed`。【实测(子代理)读 commons-lang 源码；狗蛋复核 equalsIgCase 与 chooseInstance 原文】
- 修复：启动/首次 choose 校验 version 非空，缺失时一次性 warn 并明确退化为轮询；空实例返回 `EmptyResponse`；line 149 error 降 warn 并采样。

### 7. WeightedRandomSelector 对 nacos.weight 缺失/非法零防御
`.../cloud/loadbalancer/WeightedRandomSelector.java:28,36`
- `Double.parseDouble(instance.getMetadata().get("nacos.weight"))`：Nacos 来源实例恒有该键（子代理核对 spring-cloud-alibaba 2023.0.1.0 的 hostToServiceInstance），但 supplier 也可能返回静态配置/k8s discovery 实例——一个缺键实例就能让 choose() 在 map 里抛 NPE，报错栈远离根因。【实测(子代理)读上游源码】
- 修复：`parseDoubleOr(meta.get("nacos.weight"), 1.0)`，缺失按权重 1 并一次性 warn。

## P2
### 8. 权重全 0 时仍选中被摘流实例 + 每次 new Random
`WeightedRandomSelector.java:33,37`
- 运维把 weight 置 0 摘流后，totalWeight=0 → randomValue=0 → `0<=0` 恒真，100% 选中第一个 0 权重实例，摘流失效。【复核确认】
- 修复：过滤 weight<=0 候选（全 0 时均匀随机）；比较改 `<`；`ThreadLocalRandom.current()`。

### 9. Tenant-Id / Auth-Origin 头无来源校验直接透传
`.../cloud/feign/interceptor/TenantIdInterceptor.java:40,56-60`（同 `sentinel/auth/AuthFlowInterceptor.java:38-45`、`CopilotOriginParser.java:30-35`）
- 入站头原样转发下游，且 CopilotOriginParser 把它作为 Sentinel 授权规则的 origin 依据：网关不剥离时，外部请求可伪装租户与授权 origin。【实测(子代理)；是否爆炸取决于网关】
- 修复：文档强约束网关剥离+重建，或 starter 提供内部签名头。

### 10. ExceptionFilter 对已提交响应二次写入
`.../cloud/filter/ExceptionFilter.java:23-29`
- catch 后无条件 `writeJson`，不查 `response.isCommitted()`；下游已写出部分响应时二次写入会抛 IllegalStateException 或产出 HTML+JSON 拼接的污染体；`log.error("", e)` 空消息不利检索。【实测(子代理)】
- 修复：committed 时直接 rethrow；日志带 URI。

### 11. CanaryReleaseRule 的 serviceId 是死参数、choose 忽略 Request
`CanaryReleaseRule.java:100-112,115`
- 构造参数 serviceId 注释自认「只是为了记 log」但类内从未用它记 log；`choose(Request)` 完全忽略参数（没有按 header/用户的灰度维度）——该实现是「版本亲和路由」，不是通常理解的按流量百分比金丝雀，命名易误导。metadata 键名 `"current-version"` 等散落无常量。【复核确认】
- 修复：日志带上 serviceId；javadoc 明确「仅版本亲和」；抽常量。
