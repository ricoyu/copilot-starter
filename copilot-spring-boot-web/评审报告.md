# 代码评审报告：copilot-spring-boot-web

> 评审时间：2026-09-18　范围：src/main/java 全部源码 + pom.xml + META-INF 自动装配 + resources
> 分级：P0＝线上可触发；P1＝可靠性与正确性；P2＝性能/配置陷阱/技术债
> 标注：【复核确认】＝评审人读源码原文核对；【实测】＝探针/上游源码核对过；【分析】＝代码路径推导，需特定环境复现

## 概述
Web 支撑库（限流注解/拦截器、XSS、API 签名、租户过滤器、websocket、Tomcat 统计）。本模块与 web-starter 存在 5 个全限定名完全相同的孪生类，且签名过滤器和推送接口各有一个可被直接利用的安全问题。

## 与 web-starter 的孪生副本（重要背景）
用 `diff -u` 逐对比对：`RateLimit`、`RateLimitHandler`、`RateLimitIntercepter`、`WebSocketFilter` 四对完全一致，`IdempotentTokenController` 仅 javadoc/导入顺序差异。starter 的 pom 依赖本模块 → 两份同全限定名的类同时出现在消费方 classpath，JVM 按 classpath 顺序静默加载其一；本模块没有任何 AutoConfiguration.imports，装配的永远是 starter 那份——本模块的 5 个副本类实际是死代码。今天内容一致所以行为相同，但只要哪天只改一边，行为就随构建顺序漂移且无人察觉。
- 修复方向：保留一处（建议保留 starter 或把公共类收敛进本库并由 starter 引用），删除另一处。【实测(子代理 diff)，小赫复核了 imports 与 pom 依赖关系】

## P0
### 1. ApiSignFilter 的接口签名可被任何调用方伪造
`.../web/filter/ApiSignFilter.java:54-65`
- 现象：签名的算法是 `HashUtils.sha256("uri=...&header1=v1&...")` ——对整个拼接串做 SHA-256。全文没有出现过任何服务端密钥参与计算（`CopilotMvcProperties.APISign` 也没有 appSecret/appKey 字段），客户端提交什么头就拼什么。
- 影响：任何人一行代码就能算出合法签名，接口签名防护 100% 可绕过，还提供了虚假的安全感。附带问题：`providedSignature.equals(signature)` 非常数时间比较（无密钥前提下意义不大）；`ServletUtils.getHeader` 对缺失头返回 null，`message.append(header)` 把字面量 `"null"` 拼进摘要。【复核确认：全文已读，确无密钥参与】
- 修复：改 HMAC-SHA256，服务端配置密钥；比较用 `MessageDigest.isEqual`；对配置要求而请求缺失的头直接拒绝，而不是拼 `"null"`。

### 2. ApiSignFilter 没有时间窗和 nonce 去重，抓包即可永久重放
`ApiSignFilter.java:50-71`
- 现象：timestamp 头只是被拼进哈希字符串，从未和服务器时间比较；nonce 从未存储判重（无 Redis SETNX）。而配置里专门有一个 `/timestamp` 取服务器时间接口（CopilotMvcProperties.java:78-83），说明设计意图就是防重放，实现只做了第一步。
- 影响：一条被截获的已签名请求永久有效，可无限重放。
- 修复：校验 `|now - timestamp| ≤ 窗口`；nonce 用 `SET key NX EX 窗口` 去重，重复即拒绝。【复核确认】

### 3. WebSocketFilter 暴露未认证的 HTTP→Redis PUBLISH 通道
`copilot-spring-boot-web-starter/.../websocket/WebSocketFilter.java:46-53,100-102`（本模块有同内容副本）
- 现象：`copilot.websocket.enabled=true` 时过滤器注册在 /*，路径命中 `/ws/push/**` 的请求被处理为：从 URL 尾段拼出 redis channel（攻击者可控），读取请求体原文（攻击者可控），直接 `JedisUtils.publish(redisChannel, data)`。无鉴权、无 channel 白名单、无请求体大小限制。
- 影响：任何网络客户端可向任意 channel 注入任意消息，推送给所有 WebSocket 订阅者。如果消费方应用没有网关在前面拦截，这就是活的注入入口。【复核确认：源码已读；消费方是否网关前置不在本模块控制范围】
- 修复：publish 前要求认证（内部服务令牌或登录态）；channel 限制在配置的白名单模式内；限制请求体大小。

## P1
### 4. TenantIdFilter 的租户号完全信客户端头，且有解析炸点
`.../web/filter/TenantIdFilter.java:56,76`
- 现象：`tenantId = request.getHeader("Tenant-Id")` 原样写入 ThreadContext，未与登录身份绑定；`Long.parseLong(tenantId.trim())` 对非数字头抛 NumberFormatException 且不在过滤器内捕获。
- 影响：①任何客户端改头即可伪装任意租户，下游信任 `ThreadContext.get("tenantId")` 的代码会跨租户读写；②`Tenant-Id: x` 就能让每个请求 500，是随手可做的拒绝服务。【复核确认】
- 修复：租户号从认证后的 token/session 推导，头只作提示并校验一致；非数字返回 400。若所有消费方都有网关剥离并重建该头，可降为 P2，但模块本身未强制这一前提。

## P2
### 5. 排除路径的单星号匹配多截掉一个字符
`TenantIdFilter.java:103-107`
- `pattern.endsWith("*")` 分支也用 `substring(0, length()-2)`：`"/api/*"` 截成 `"/api"` 做前缀匹配，`/apitest` 被误判为排除项，租户头必检被跳过。双星号分支恰好 -2 才是对的。【复核确认：off-by-one 直接可见】
- 修复：单星号截 1 个字符，或统一改用 AntPathMatcher。

### 6. TomcatThreadPoolStatisticFilter 提前返回时不写响应也不放行
`.../web/filter/TomcatThreadPoolStatisticFilter.java:44-56`
- `findServices()`/`findConnectors()` 为空时 `return`，既不写响应也不调用 `filterChain.doFilter`，客户端收到空的 200；非 Tomcat 容器时 line 52 强转失败直接 500。统计路径本身未鉴权（开关只有 `copilot.filter.pool-statistic=true`），内部线程池规模可被外部探测。资源侧无泄漏（过滤器不持有请求级状态）。【复核确认】
- 修复：提前返回前写明确 404/错误并放行其他请求；接口挂管理端口或鉴权。

### 7. IdempotentTokenController 两份副本都没被装配，幂等 token 功能整体不可用
`copilot-spring-boot-web-starter/.../autoconfig/CopilotMvcConfiguration.java:158-161`
- `IdempotentIntercepter` 无条件注册（line 199），但发 token 的 `idempotentTokenController()` `@Bean` 被注释，两份 `@RestController` 副本所在模块都没有 imports 注册。除非用户碰巧组件扫描到 `com.awesomecopilot.boot.web.controller`，`GET /idempotent-token` 404 → 所有 `@Idempotent` 接口以 MISSING_IDEMPOTENT_TOKEN 拒绝，功能实际是死的；而扫描到之后该端点又无鉴权无限流，Redis hash 可被打到无界增长。【实测(子代理)，小赫复核注释状态】
- 修复：starter 里用 `@ConditionalOnProperty(copilot.mvc.idempotent-enabled)` 正式注册，删两份死副本，并给端点加保护。

### 8. RateLimit 注解契约自相矛盾
`.../web/annotation/RateLimit.java:45-49,59`（两份副本一致）
- ①类 javadoc 说「expire 秒内最多 count 次」，属性注释说 window 单位毫秒（starter 的拦截器把毫秒直接当秒用，见 web-starter 报告 P0#1，是同一根因）；②`handler()` 无 default，使用时被迫填实现类，而注释承诺的「默认返回 4290000」分支永远不可达（注解 Class 值不可能为 null，拦截器 `handlerClass != null` 恒真）。【复核确认】
- 修复：单位统一为秒（或拦截器换算）；`handler()` 加 `default RateLimitHandler.class` 并改判 `!= RateLimitHandler.class`。
